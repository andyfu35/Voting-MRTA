# Fully Decentralized Preference Voting-MRTA

This experiment removes the terminal as the final assignment authority and tests whether a robot team can make a shared multi-task decision through peer-to-peer preference exchange and quorum commit.

## Core idea

The multi-task cost model remains shared and unchanged. Every method receives the same robot-task cost matrix `C_ij`.

The key change is the definition of a vote. A robot no longer sends only one sampled candidate. For every task, it produces and broadcasts the complete candidate preference distribution:

```text
P_r[i, j] = preference from voter r for candidate robot i on task j
```

A complete preference message therefore contains the whole robot x task preference matrix generated by that voter's policy.

## Why complete preferences matter

A single winner-only ballot discards second- and third-choice information. This is especially harmful in multi-task allocation because the locally best robot for several tasks may be the same robot, while the final assignment must respect robot capacity.

Complete preference vectors preserve alternative candidates so the assignment solver can choose a feasible global matching without treating all non-winners as equally unsupported.

## Decentralized architecture

There is no terminal in the experiment.

Each synchronous allocation round has four phases:

1. **Shared cost evaluation** - all voting policies use the same `C_ij` definition.
2. **Peer preference broadcast** - each active robot broadcasts its complete preference matrix to every other active robot.
3. **Local assignment** - each robot aggregates only the preference messages it actually received and independently solves the same capacity-constrained assignment problem.
4. **Quorum commit** - robots broadcast the assignment they computed. A robot commits only when one identical assignment receives more than the configured quorum fraction of the known active membership.

The local assignment objective is:

```text
maximize sum_ij V_ij x_ij
```

where `V_ij` is that receiver's locally aggregated preference support.

The assignment constraints are:

```text
sum_i x_ij = 1      for every task j
sum_j x_ij <= 1     for every active robot i
```

## No strict synchronization requirement

Robots are intentionally allowed to see different subsets of peer messages. A node does not wait until every other node has sent exactly the same information.

The research hypothesis is:

> With enough independently participating robots, randomly missing a minority of preference messages should have a smaller effect on the aggregate policy mixture, so the locally computed assignments should become more stable as team size increases.

This is statistical redundancy, not a guarantee that every node has identical state.

## Voting-policy diversity

All robots use the same cost matrix, but voters may transform that cost into preferences using different policies.

The decentralized experiment compares:

- `Homogeneous Inverse a=3` - every voter uses the same strong policy. This is a control condition.
- `Heterogeneous Strong Policies` - active voters are randomly balanced across:
  - Inverse `alpha=2`
  - Inverse `alpha=3`
  - Softmax `beta=2`

Because the heterogeneous voters produce different complete preference distributions, packet loss changes the policy mixture seen by each receiver. Increasing robot population should make that random mixture error smaller if group redundancy works as intended.

## Communication model

Both preference broadcast and assignment-proposal broadcast use peer-to-peer links with stop-on-success retransmission.

Experiment settings:

```text
Robot counts          = 10, 20, 40, 60, 80, 100
Trials                 = 50 per robot count
Task load              = 50% of active robot count
Permanent robot failure= 5%
Maximum attempts       = 3
Per-attempt packet loss= 30%, 50%, 70%
```

The theoretical delivery probability after three attempts is:

```text
1 - p_loss^3
```

so the three tested conditions correspond to approximately:

```text
30% loss -> 97.3% delivered
50% loss -> 87.5% delivered
70% loss -> 65.7% delivered
```

## Quorum

The experiment tests:

```text
40%+, 50%+, 60%+, 67%+, 75%+
```

`50%+` is a strict majority because the required integer count is:

```text
floor(q * N_active) + 1
```

The 40% threshold is intentionally included as an unsafe comparison. Under the non-Byzantine assumption and a common active-membership view, strict-majority-or-higher quorums cannot have two different assignments each supported by disjoint majorities of the same voters. Lower quorums may permit conflicting commits.

## Metrics

The main metrics are:

- **Modal Assignment Share** - fraction of active robots proposing the most common local assignment before quorum.
- **Strict Agreement Rate** - fraction of rounds where every active robot independently computes the same assignment.
- **Reference Match Fraction** - fraction of local assignments matching the full-information preference assignment.
- **Safe Commit Rate** - fraction of rounds with at least one commit and no conflicting committed assignment.
- **Split-Brain Rate** - fraction of rounds where different robots commit different assignments.
- **Committed Node Fraction** - average fraction of active robots that locally observe enough proposal support to commit.
- **Committed Optimality Gap** - cost gap of a safely committed assignment relative to centralized cost-optimal assignment.
- **Peer Message Delivery Rate** - realized delivery rate after retransmission.
- **Average Peer Transmission Attempts** - stop-on-success communication overhead.

## Important interpretation

This experiment removes the central decision authority, so the assignment decision is decentralized. However, it still assumes:

- synchronous allocation rounds
- a common active-membership view at the beginning of a round
- non-Byzantine robots
- deterministic assignment/tie-breaking rules

Therefore it should be described as a **fully decentralized assignment authority under controlled synchronous and crash-failure assumptions**, not as a general Byzantine asynchronous consensus protocol.
